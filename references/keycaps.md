# 鍵帽：封著世界的透明盒子

鍵帽是這支片最有辨識度的發明：**它們不是按鍵，是世界的容器**。從外面看是體素微縮模型，鑽進去是寫實的遼闊世界。參考圖：`../benchmark/frames/k_*.jpg`、`t_16.6.jpg`、`t_19.0.jpg`、`t_22.5.jpg`。

## 1. 一顆鍵帽的構造

```
  ┌─────────────┐  頂面：微凹（dish 0.05 cm），霧面樹脂（ResinFrost，粗糙度 0.22），反射一條柔和的螢幕白光
 ╱               ╲ 側壁：拋光透明樹脂（Resin，粗糙度 0.03，IOR 1.5），藍灰色調，菲涅爾亮邊，折射
│   空氣（透明）    │ 上半部是空的玻璃罩
│▓▓▓ 體素地景 ▓▓▓▓│ 下半部 35–60 % 高：方塊地形，頂面是地表
│███ 地層剖面 ████│ 側面看得到切面：頂層顏色、2 層土、再往下是石頭；水從切面流下（瀑布鍵）
└─────────────────┘ 開口朝下，坐在鍵盤底板上；底板本身也是一張連續的暗色地圖
```

| 參數 | 值（cm = BU） | 來源 |
|---|---|---|
| 鍵距 1u | 1.905 | 標準機械鍵盤 |
| 底部 | 1.80 × 1.80（寬鍵：1.80 + (u−1) × 1.905） | `keycap.BASE` |
| 頂面內縮 | 每邊 0.27 | `TOP_INSET` |
| 高度（OEM 輪廓，按列） | 1.10／1.00／0.95／0.90／0.95／1.00 | `ROW_H` |
| 壁厚 | 0.06（Solidify 往內） | |
| 體素格 | 0.085（每顆 1u 鍵約 15 × 15 格） | `build_key(cell=)` |
| 底板到鍵帽底 | 0.35 | `GAP_Z` |

建立：`K.shell()`（外殼）+ `K.build_key()`（外殼＋地景＋水＋內部點光）；整把：`K.build_keyboard()`。

**外殼不投影**（`visible_shadow = False`），讓鍵帽裡的點光能照到鄰鍵和角色腳底，在 EEVEE 和 Cycles 都成立。

## 2. 地景目錄（`keycap.BIOMES`）

| 名稱 | 外觀 | 光色 | 用在 |
|---|---|---|---|
| `meadow` | 綠草、左上池塘、小丘；`after=True` 時中間多一棵樹 | 淡綠 | **主角鍵**（Enter），進出都是它 |
| `waterfall` | 後半高台草地＋一條小溪，從切面流下成瀑布；前半是水 | 淡青 | 第二個落腳點 |
| `splash` | 整顆是水，頂面泡沫 | 淡青 | 第一個落腳點，落地濺起水花 |
| `lake` | 淺水湖＋中間小島和樹 | 青 | |
| `coral_sea` | 沙底、白色珊瑚、高水位、氣泡 | 亮青 | |
| `deep_ocean` | 深藍水體 | 藍 | |
| `snow_crater` | 白雪地＋兩個黑色坑 | 白 | 踩到時亮成純白 |
| `night_city` | 深藍地面＋高低樓房，窗戶自發光 | 冷白 | 踩到時窗光亮起 |
| `basalt` | 黑色岩地＋白點 | 淡紫白 | |
| `lava` | 暗紅岩＋中央發光岩漿 | 紅 | **固定發光**，不受點亮控制；全片唯一的紅色，放在左下 |
| `terraces` | 同心等高線台地（薄荷綠） | 淡綠 | |
| `forest_river` | 綠地、樹叢、蜿蜒小河 | 淡綠 | |
| `glacier` | 淺藍階梯冰塊 | 冰藍 | 多放鍵盤右側邊緣 |
| `snow_forest` | 雪地＋灰色樹 | 白 | |
| `beach` | 米色沙地、零星草、一側是水 | 暖白 | |
| `river_panorama` | 長河谷：河水、綠岸、雪頂樹 | 淡青 | **空白鍵**（長條構圖適合橫移） |
| `empty` | 只有霧面樹脂 | — | 約 22 %，留白讓有內容的鍵更突出 |

**排列規則**（`assign_biomes`）：相鄰的鍵盡量冷暖交錯；只有一個異色點（紅光鍵）；寬鍵放全景，標準鍵放單一地標；故事路線上的鍵用 `overrides` 指定（範例的 `common.BIOME_OVERRIDES`）。

新增地景：寫一個 `b_xxx(nx, ny, H, r, seed=0)` 回傳 `{'h': 高度格, 'top': 頂面材質鍵, 'side': 側面函式, 'water': 水位格, 'light': 光色}`，加進 `BIOMES`。材質鍵必須在 `_VOX` 裡。

## 3. 點亮敘事（最容易被忽略的巧思）

| 時間 | 鍵盤狀態 | 怎麼做 |
|---|---|---|
| 第一次經過（S05–S08） | **大部分鍵是暗的**，只看得到暗綠暗青的輪廓；角色**踩到的鍵**從內部亮起並一直亮著，連成足跡 | `keyboard_set(awake=False)` 會依 `state.lit_trail` 把已踩過的鍵設為亮；本鏡頭內的落地由 `common.wake()` 呼叫 `K.light_up()` 和 `K.press()` |
| 回來時（S17） | **整把鍵盤全亮**，由主角鍵向外漣漪式亮起 | `K.wave_on(kb, f0, f1, 'R3K12')` |

機制：每個地景物件有自訂屬性 `obj['glow']`（0–1），所有體素材質用 Attribute 節點（OBJECT 類型）讀它驅動自發光；鍵帽內的點光能量同步。`light_up` 會先閃到 1.8 再回到 1.0（`expo_out`）。

**光是敘事**：第一次經過時世界在沉睡，回來時整個世界醒了，一句台詞都沒有。

## 4. 互動反應

| 事件 | 反應 | 函式 |
|---|---|---|
| 落地 | 鍵帽下沉 0.12 再 `back` 回彈；裡面的地景亮起；水鍵濺起泡沫方塊 | `K.press`、`K.light_up`、`FX.splash`（位置 = 鍵頂 − 0.45） |
| 鑽入 | 頂面泛起圓形漣漪；鍵帽閃到 2.6；角色縮小沉入 | `FX.ripple(normal='Z')`、`K.light_up(peak=2.6)` |
| 彈出 | 頂面爆閃白光、方塊四散、一圈漣漪 | `FX.burst` |
| 腳底透光 | 站在發亮的鍵上時角色底部被染成粉橘 | 自動：鍵帽內點光 + 外殼不投影 |

## 5. 微縮版和寫實版對位

主角鍵（Enter）的體素地景和鍵帽裡的寫實草原**是同一張版圖**：

- 版圖存在 `shots.json` 的 `layout`（**正方形**歸一化座標 u 向右、v 向後）。寬鍵裡版圖佔中間的正方形區域（`_sq_u`／`_col_of` 換算），左右兩側是延伸的草地。
- 體素版：`b_meadow(layout=...)` 依 layout 挖池塘、堆小丘；`after=True` 時在 `tree` 位置長出樹柱。
- 寫實版：`env.layout_to_world(uv, size=120)` 把同一個座標放大到草原（120 cm 寬）。
- 在體素版上放東西：`K.diorama_point(kb, 'R3K12', u, v)` 回傳該點地表的世界座標（S17 用它放小 Clawd、小巨人、小果實）。

這樣 S16 結尾的正俯視（池塘一角在左上、樹冠在左、巨人在右）和 S17 開頭透過鍵帽看下去的體素版，觀眾不用思考就能認出是同一個地方。

## 6. 效能

- 整把 84 顆鍵、`cell=0.085` 約 25–35 萬面；建場景約 20–60 秒（純 Python 迴圈）。
- 只拍局部時用 `only={…鍵號}`，其他鍵只建空殼。
- 遠景（S02 房間）用 `cell=0.17`、`lights=False`。
- 84 顆點光在 EEVEE 沒問題；Cycles 開 `light tree`（4.x 預設開）。
