# 基準片拆解：《claude.MP4》

> 這是 skill 的對標作品。`examples/claude-keycap-world/` 是照這份拆解寫的逐鏡頭 Blender 實作。圖都在 `../benchmark/`（關鍵幀只收錄了一部分，檔名是秒數）。

> 片長 60.0s｜1024×576｜30fps｜H.264 + AAC 44.1kHz 立體聲｜18 個鏡頭（含結尾黑場）
> 參考素材都在 `../benchmark/` 裡：`sheets/`（全片 3fps 拆幀，每張 4 秒）、`keyframes/`（原尺寸關鍵幀，檔名是秒數）、`keycaps/`（鍵盤段原尺寸幀）、`transitions/`（關鍵轉場逐幀條）、`audio_spectrum.png`（頻譜）。
>
> 第 10–12 節是三個專題深挖：**鍵帽微縮世界**、**拉出揭示轉場**、**光影設計**。

## 0. 一句話

**終端機裡閃爍的游標活了過來，變成 Claude Code 的像素小怪（下面叫它 Clawd），從螢幕走到鍵盤上，鑽進一顆鍵帽裡的微縮世界。它把一根「游標」種成一棵樹，樹上結出成百個小分身，小分身拼成一個巨型的自己。最後鏡頭一路拉出鍵帽，回到終端機：螢幕上那個 2D 像素 logo 旁邊，游標又開始閃。**

整片講的是「一個游標 → 一個角色 → 一群分身 → 一個更大的造物 → 回到游標」的閉環。

---

## 1. 製作方式判斷：3D 動畫管線，最可能是 Blender

> 初稿曾判斷為 AI 視頻生成，複查後推翻。當初的「證據」其實都是設計選擇：側面看到的「鼻子」是 3/4 視角下的側邊手臂；眼睛形狀變化是眨眼、瞇眼的表演；程式碼畫成虛線膠囊是刻意的抽象化；1024×576、30fps 是上傳平台轉碼的結果。

**為什麼是 3D 動畫，不是生成：**

| 證據 | 位置 |
|---|---|
| **場景狀態跨鏡頭保持**：角色踩過的鍵帽會亮起並一直亮著，在 23.8s 的全景裡連成一條「足跡路徑」（空白鍵 → 瀑布鍵 → 湖鍵 → 森林鍵 → 雪鍵） | 20–24s |
| **佈局跨尺度對應**：俯視寫實草原的池塘、樹、巨人位置，和鍵帽裡體素微縮版完全一致 | 51.3–52s |
| **遞迴結構精確**：巨人由幾百個完整的小 Clawd 組成，眼睛是規則缺口，堆砌時一層層由下往上 | 43–48s |
| **進出同一顆鍵帽**，微縮版裡保留了角色造成的改變 | 27s／52s |
| 剪點卡 120 BPM 拍點、游標閃爍間隔剛好一拍 | 全片 |

**為什麼是 DCC 軟體離線渲染（Blender／C4D／UE5 一類），不是程式碼即時渲染（three.js 一類）：**

| 畫面特徵 | 說明 |
|---|---|
| **多層透明正確疊加** | 前排鍵帽透出後排鍵帽，後排又透出裡面的地景，折射都正確。three.js 的 transmission 只折射不透明物體，透明疊透明會穿幫；這種效果是路徑追蹤（Cycles）的強項 |
| **乾淨的實體景深** | 前景草葉虛化後疊在清晰的角色前面，邊緣沒有光暈或描邊，是渲染時的物理相機景深，不是後期 DOF |
| **全域光照的色溢** | 紅光鍵把鄰鍵染紅；發光鍵帽把角色腿底染成粉橘；草原地面反光讓角色陰影面帶綠 |
| **超高密度寫實草地** | 數百萬草葉、逆光透光、露珠、雛菊，典型的「散佈系統＋植物素材庫」（Blender 的 Geo-Scatter／Botaniq／Grass Essentials 一類，或 UE5 的 Megascans） |
| **剛體堆積** | 幾百個小 Clawd 落地後翻滾、互相碰撞、堆成自然的一片，是物理模擬（Bullet 剛體）的結果 |
| **體積光與大氣** | 遠景霧化、光膜的半透明體積感、綠色光束 |

**Blender 的可能性最高**：2D 像素 → 體素 → 倒角實體的形變、樹冠由方塊實例組成、分身堆成巨人，都是 Geometry Nodes 的標準做法（像素圖 → 點 → 實例化方塊 → 合併重構網格）；畫面整體也很像 Cycles／EEVEE 搭配草地散佈素材的質感。C4D＋Redshift／Octane 或 UE5 也做得出來，單憑畫面無法百分之百確定。程式碼渲染的可能性很低。

**結論**：這支片的水準來自四件事：**導演設計**（概念、母題、尺度敘事）、**場景的連續性**（同一個 3D 世界，狀態跨鏡頭保持）、**物理渲染品質**（路徑追蹤的透明、景深、GI，加上寫實植被素材）和**剪輯節奏**（硬切卡 120 BPM 拍點）。

## 2. 敘事結構（三幕＋回環）

| 段落 | 時間 | 場景 | 亮度（0–255 均值） | 音樂 | 戲劇功能 |
|---|---|---|---|---|---|
| **序：誕生** | 0–11.5s | 終端機內部（暗、冷） | 9–45 | 安靜 → 打字聲 → 上行琶音 | 游標 → 2D 像素 → 3D 角色；揭示「我們在螢幕裡」 |
| **一幕：越界** | 11.5–28.4s | 鍵盤（暗底，鍵帽裡透出青、綠、白、紅） | 40–70 | 主旋律進入，每拍都有起音 | 穿出螢幕，探索鍵帽世界，每踩一顆鍵就「激活」它 |
| **二幕：內在世界** | 28.4–40.9s | 鍵帽裡的草原（明亮、暖） | 100–138 | 收小、留白 | 從天而降，發現游標，種下它，長成樹 |
| **高潮：一變多，多成一** | 40.9–51.9s | 草原 | 105–130 | 40.0s 重拍，全片最響（-13 dB），八分音符脈衝 | 果實落下變成分身，分身拼成巨人 |
| **尾聲：回家** | 51.9–60s | 鍵帽 → 鍵盤 → 終端機 | 128 → 32 | 高頻閃爍掃頻 → 收尾 | 一鏡拉出，3D 角色仰望螢幕上的 2D 自己，游標再次閃爍 |

**能量曲線**：暗 → 暗中帶彩 → 全亮 → 全亮且最滿 → 回到暗。進入「內在世界」等於走進光裡，這是整片最大的視覺反差，也是情緒高點的鋪墊。

## 4. 視覺系統

### 4.1 角色規範（Clawd）

- **造型**：橫向長方體身體（寬:高:深 ≈ 1.4 : 1 : 1），兩側各一個小方塊手臂，底部 4 根方柱短腿（前後各兩根），正面兩個豎長方形黑色眼睛，**沒有嘴**。原型就是 Claude Code 啟動畫面的那個像素小怪。
- **三種形態**（全片的核心視覺發明）：
  1. **2D 像素**：平面、硬邊、像終端機字元（開場和結尾的螢幕上）
  2. **體素**：看得見網格線的小立方體陣列（成形過程、巨人）
  3. **黏土實體**：大圓角倒角、啞光、像軟陶或塑膠玩具（主要形態）
- **表演**：全靠眨眼（眼睛壓成橫線）、身體傾斜、蹦跳、轉身。沒有表情，用「姿態」演戲。
- **顏色**：亮面 `#CC6549`～`#CC6B57`，背光面 `#AC553C`；接近 Claude 品牌橘 `#D97757`，偏紅一點、飽和度略低。

### 4.2 材質表

| 材質 | 特徵 | 重現要點 |
|---|---|---|
| **角色黏土** | 啞光、粗糙度高、極細微的表面顆粒，大倒角上有柔和高光 | roughness 0.6–0.75，倒角半徑約邊長 6–8%，加一點次表面散射感（邊緣偏暖） |
| **終端機空間** | 近黑藍底 `#00060D`～`#191D24`；「程式碼」是發光的灰色膠囊虛線；有金屬導軌線 | 把文字抽象成長短不一的圓角條，排成行，放在不同深度做視差 |
| **樹脂鍵帽** | 透明、帶藍灰色調 `#4D6472`；裡面封著體素微縮地景（水、瀑布、草地、雪地、夜城、紅色岩漿）；邊緣有折射和菲涅爾亮邊 | 透射＋折射＋粗糙度低的表面，內部地景比外殼亮，所以像「發光的盒子」 |
| **空白鍵** | 一整條長河谷全景（水、樹、雪山） | 長條形景觀，橫移時有視差 |
| **紅光鍵** | 唯一的紅色自發光點 | 色彩上的「標點符號」，在暗色的鍵盤上錨定視線 |
| **寫實草地** | 長短不一的草葉、露珠、雛菊、黃色小花、藍色小花；前景大量虛化 | 草的層次至少三層（前景虛化大草葉、中景主體、背景霧化），露珠是高光點 |
| **體素植物** | 樹冠是一團團亮綠色小立方體，樹幹是有樹皮紋理的方柱 | **寫實環境＋體素造物**的混搭是這片的招牌質感 |
| **天空與遠景** | 藍天 `#82ADE9`、地平線偏白 `#C8D8E7`、遠樹 `#9CB8E2`，濃厚大氣透視 | 遠景低對比、偏藍，像薄霧 |

### 4.3 光線與色彩腳本

- **終端機／鍵盤段**：冷藍黑環境＋**來自角色下方的橘色輻射光**（2D 拼成時）＋側上方的冷白輪廓光。角色是畫面裡唯一的暖色，所以不管多小都能一眼找到。
- **草原段**：正午偏後的暖陽，從左上方來；天光偏藍；**葉影落在角色臉上**（30.5s）；高光溢出（bloom）在草尖和雛菊上；38.5s 有一道綠色光束掃過樹冠（像鏡頭光暈）。
- **互補色結構**：全片只有「橘 vs 藍/青」和「橘 vs 綠」兩組對比。橘色永遠屬於角色和游標，其他東西不准用這個色。

### 4.4 鏡頭語言（光學）

- **長焦感、淺景深**：幾乎每個鏡頭前景都有虛化（游標行、鍵帽、草葉），主體清晰，背景柔焦。這是讓 1024×576 也顯得「貴」的關鍵。
- **低機位**：80% 的鏡頭架在角色眼睛高度或更低，讓一個幾公分大的小東西顯得「有份量」。
- **微距尺度**：用景深和低機位把桌面拍成地形、把草拍成森林。

| 靜止長鏡頭 | 巨人堆砌 | 奇觀需要穩定的畫框，讓觀眾看清每一塊 |
| 快速升到正俯 | 巨人 → 俯視 | 為「透鏡揭示」轉場做準備 |
| 一鏡到底大拉出 | 結尾 | 把三層尺度（草原 → 鍵帽 → 鍵盤 → 螢幕）一次串起來 |

## 6. 轉場手法（共 6 種）

1. **形變轉場（Morph）**：游標 → 2D → 體素 → 實體，一個鏡頭內完成，不剪。
2. **尺度揭示硬切**：從特寫直接切到大遠景，主角變成一個點（8.03s）。
3. **穿膜轉場**：角色穿過發光的弧形光膜，光膜 = 螢幕玻璃；外側接同心圓波紋（10.5–12s）。
4. **撞擊漣漪轉場**：角色撞進鍵帽表面，表面像水一樣起圓形波紋 → 切到內在世界從天而降（28s）。
5. **透鏡／光圈揭示**：俯拍畫面中央開出一個圓，裡面是同一場景的微縮版，再拉出（51.9s）。這是「Powers of Ten」式的尺度套疊。
6. **動作匹配硬切**：同一個動作從不同機位接上（穿膜內 → 穿膜外、跳 → 落）。

**規律**：**每次換「世界」都有一個物理介面**（螢幕玻璃、鍵帽樹脂表面），角色要穿過這個介面，介面就產生波紋或光。所以轉場本身就是故事的一部分，不是剪輯技巧。

## 7. 母題與細節巧思（這片最值得學的部分）

1. **游標母題貫穿全片**：
   - 0s：終端機的橘色游標，以 120 BPM 的拍子閃爍
   - 7.7s／11–12s：遠處桌面上立著另一根橘色游標
   - 32s：草原裡立著一根橘色游標
   - 36s：從地裡長出的樹幹，最初就是一根**跟游標同比例的深色方柱**
   - 59s：結尾 2D logo 旁的游標又開始閃
   游標 = 種子 = 起點。開頭和結尾用同一個東西收束，形成閉環。
2. **2D ↔ 3D 鏡像**：開頭 2D 像素「變成」3D；結尾 3D 的它抬頭看著螢幕上的 2D 自己。同一個角色的兩種存在形式對望。
3. **遞迴／分形**：巨人是由**幾百個完整的小 Clawd**（每個都有眼睛）拼起來的；巨人的眼睛是「缺掉的格子」。放大是它，縮小也是它。
4. **一變多，多成一**：一根游標 → 一棵樹 → 很多分身 → 一個巨人。很容易讀成「Claude Code 派出許多 subagent，合力完成大工程」的隱喻（作者意圖是推測，但結構確實是這樣）。
5. **尺度套疊**：螢幕裡（微型）→ 鍵盤上（玩具尺度）→ 鍵帽裡（再微型）→ 草原（反轉成巨大）→ 拉出（全部縮回去）。觀眾的尺度感被反覆翻轉兩次。
6. **改變會留下來**：結尾拉出時，那顆鍵帽裡的微縮地景**多了一棵結紅果的小樹和小 Clawd、巨人**——它在裡面做的事被「存檔」了。
7. **鍵帽 = 世界**：每顆鍵都封著一種地貌，踩上去就激活（水濺起、發光）。「每次按鍵都在創造一個世界」。
8. **游標閃爍卡拍**：開場的閃爍間隔是 0.5s，正好等於配樂的一拍（120 BPM）。畫面的第一個節奏就是音樂的節奏。
9. **唯一的暖色**：橘色只屬於角色系統（角色、游標、分身、果實），所以觀眾的視線永遠被它牽著走。
10. **紅光鍵**：鍵盤上固定位置的一顆紅色自發光鍵，像地圖上的地標，讓好幾個鍵盤鏡頭的空間連貫。
11. **小動作讓角色活起來**：瞇眼、看向游標、繞著它走一圈、仰望。角色從不說話，只用「注意力的方向」演戲。

## 8. 聲音與節奏

### 8.1 速度與剪輯網格

- **120 BPM**，一拍 0.5s，一小節 2s。起音偵測顯示 12.03／12.54／15.02／15.53／16.04／18.04／20.04…幾乎全落在 0.5s 網格上。
- **17 個硬切裡有 14 個落在拍點上**（8.03、9.03、10.53、11.53、17.53、20.03、24.03、30.03、33.03、36.03、42.03、43.03、48.03、59.03）。不在拍點上的 3 個（28.37、40.93、51.90）都是**動作驅動的轉場**（甩鏡、果實落地、升到俯拍），讓動作本身決定切點。
- **規則**：靜態或對話式的切點卡拍；動作中的切點跟動作走，但動作的高點（落地、撞擊、果實開始掉）要卡拍。

### 8.2 能量曲線（響度 dB）

```
 0– 2s  -57 → -46  幾乎無聲，只有零星點擊聲
 2– 3.5 -29        快速點擊（像打字）——游標開始「寫」
 4– 6.5 -27        上行的音高掃頻／琶音（頻譜上清楚可見）——成形
 8–11.5 -30        稀疏
12–28   -16～-21   主題進入，每拍有起音——旅程
28–39   -22～-28   收小、留白——進入內在世界、種樹
40.0    -13        全片最響的重拍——果實落下
40–48   -14～-17   八分音符脈衝（0.25s 間隔）——分身湧動、堆砌巨人
48–52   -15～-17   維持高能量——巨人邁步
52–58   -19～-20   高頻閃爍上行掃頻——拉出
59.5    -30        收尾
```

- 頻譜上 4–6.5s 有一條清楚的**上行音高線**，就是「成形」的音效／音樂動機；53–55s 有一團**高頻閃爍**對應拉出的魔法感。
- 調性中心大約在 E（B、E 兩個音最強），僅供參考。
- **設計原則**：「進入新世界」時音樂收小（28s），「奇觀」時音樂爆發（40s）。安靜在前，爆發在後，對比才有力。

## 9. 可複刻的「配方」（抽象成模板）

把這支片抽象成一套可重複使用的結構：

1. **選一個「源點符號」**（游標）：產品介面裡最小、最常見的元素。它就是種子，開頭和結尾都要出現。
2. **讓符號變成角色**：2D → 體素 → 實體的三段式形變。
3. **至少兩次「穿越介面」**：螢幕玻璃、鍵帽表面……每次穿越都換一個世界和一套色調，穿越時要有物理反應（光、波紋、水花）。
4. **反轉尺度**：讓觀眾以為很小的地方，裡面是遼闊的世界。
5. **母題回收**：源點符號在新世界裡再次出現，被角色「使用」（種下）。
6. **奇觀高潮**：一變多 → 多成一（遞迴的自我複製）。卡在全片最強的重拍上。
7. **一鏡拉出回到起點**：把所有尺度串起來，角色與自己的源頭對望，源點符號再次開始動作（閉環）。
8. **節奏**：120 BPM，硬切卡拍；長鏡頭給形變和奇觀，短鏡頭給揭示和反應；先收後放。
9. **色彩紀律**：主角色只屬於角色系統，其他一切用它的互補色。
10. **光學紀律**：低機位、淺景深、前景虛化。

## 10. 深挖①：透明鍵帽裡的微縮世界

> 參考：`../benchmark/frames/`（k_15.5～k_54.6，檔名即秒數）

### 10.1 一顆鍵帽的構造（由外到內）

```
  ┌─────────────┐  ← 頂面：微霧面，有一條柔和的白色反光（螢幕光）
 ╱               ╲ ← 側壁：拋光透明樹脂，帶藍灰色調，邊緣有菲涅爾亮線和折射扭曲
│  ~ ~ 空氣 ~ ~   │ ← 上半部：透明的空樹脂（像玻璃罩）
│▓▓▓▓ 體素地景 ▓▓▓│ ← 下半部 40–70% 高：方塊地形，頂面是地表（草／雪／水）
│████ 地層剖面 ███│ ← 側面看得到切面：土、石的分層，水會從切面邊緣流下（瀑布鍵）
└─────────────────┘ ← 底：坐在鍵盤底板上，底板本身也是一張連續的地圖
```

- **鍵帽形狀**：標準的機械鍵盤鍵帽輪廓（頂面微凹、四邊梯形斜壁），寬鍵（Shift／Enter／空白鍵）用來放「全景型」地景。
- **鍵帽沒有任何字符**。它們不是「按鍵」，是「世界的容器」。
- **內容是體素（方塊）風格**，跟外面寫實的草原形成兩個解析度：從外面看是 Minecraft 式的低解析度微縮；鑽進去之後變成寫實世界。**同一個世界，兩種細節層級。**
- **底板也是世界**：透過透明鍵帽往下看，底板上是一整張連續的綠色地圖（池塘、草地、樹叢），所以整把鍵盤是「一塊大陸，被切成很多格展示」。

- **只有一個「異色點」**（紅光鍵），像地圖上的「你在這裡」。
- **寬鍵放全景，標準鍵放單一地標。**

### 10.3 鍵盤的「點亮」敘事（最容易被忽略的巧思）

| 時間 | 鍵盤狀態 | 畫面亮度 |
|---|---|---|
| 13–27s（第一次來） | **大部分鍵帽是暗的**：內容只能看到暗青、暗綠的輪廓。只有角色**踩過的鍵**會從裡面亮起來（雪原變純白、夜城亮出窗光、水鍵變亮青），而且踩過就一直亮著，像留下足跡 | 40–70 |
| 52.8–54.6s（回來時） | **整把鍵盤全亮**：每顆鍵都是飽和的彩色地景，連成一片 | 約 128 |

也就是說：**角色的旅程把世界「點亮」了**。第一次經過時世界在沉睡，回來時整個世界都醒了。這是用光線完成的敘事弧線，一句台詞都沒有。

### 10.4 鍵帽的互動反應

- **落地**：裡面的水濺起、泡沫翻湧（水鍵）；或從內部亮起（雪原、夜城）。
- **離開**：從鍵帽頂面冒出一團白色霧光（53.3s 角色從主角鍵裡彈出時）。
- **鑽入**：鍵帽表面像水面一樣泛起圓形漣漪，中心有一個透明氣泡（28s）。
- **腳底透光**：角色站在發光的鍵帽上時，腿和身體底部被下方的光染成粉橘色（16.5s、19s），這是讓角色「站在」鍵帽上而不是「貼在」上面的關鍵細節。

## 11. 深挖②：「原來是鍵帽裡的微縮世界」——拉出揭示的逐幀拆解

> 參考：`../benchmark/transitions/g_lens_reveal.jpg`（51.0–53.4s，10fps）、`e_pullout.jpg`

這是全片設計最精密的一個轉場，拆成 6 拍：

| 拍 | 時間 | 畫面 | 手法 |
|---|---|---|---|
| ① 拔高 | 51.0–51.3s | 鏡頭從巨人身旁快速升起，前景的體素樹冠高速掠過畫面 | **前景遮擋當擦除（wipe）**：樹冠蓋住畫面一瞬間，掩護機位的大幅變化 |
| ② 俯視定格 | 51.3–51.6s | 正上方俯視：左邊一團樹冠，右邊躺著巨人，左上角一塊深色區域（池塘），草地上散著白色小花 | **為揭示擺好「版圖」**：這個構圖就是待會兒微縮版的佈局 |
| ③ 種子光點 | 51.6–51.8s | 樹冠和巨人之間出現一個小小的白色光點 → 擴成一個圓環 | 用一個極小的光點當「鑰匙孔」，觀眾的眼睛會被吸過去 |
| ④ 透鏡 | 51.8–51.9s | 圓環變成一顆**玻璃球透鏡**，透鏡裡是**同一個佈局的體素微縮版**（池塘、結紅果的樹、躺著的巨人、小 Clawd） | **細節層級切換（LOD swap）**：透鏡外寫實，透鏡內體素 |
| ⑤ 硬切到鍵帽 | 51.90s | 整個畫面變成透過樹脂頂面看下去的微縮地景，鍵帽的透明邊框出現在畫面邊緣 | 透鏡「接管」全畫面，配合硬切 |
| ⑥ 一路拉出 | 52.0–54.6s | 持續上升後拉：看到鍵帽的四面牆 → 隔壁鍵帽**依序亮起**（雪原、珊瑚海、梯田）→ 53.3s 角色從主角鍵裡**彈出**（頂面冒白霧光）→ 拉出整把鍵盤，螢幕底座入鏡 | 每多拉一段，就多揭示一層「容器」 |

**能讓這個轉場成立的五個前提**：
1. **佈局連貫**：俯視寫實世界和體素微縮版的元素位置完全對應（池塘在左上、樹在中間、巨人在右）。觀眾不需要思考就能認出「這是同一個地方」。
2. **進出同一顆鍵**：27–28s 鑽進去的那顆寬鍵，就是 52s 拉出來的那顆。
3. **改變被保留**：微縮版裡**多了**一棵結紅果的樹、躺著的巨人、小 Clawd。原本的鍵帽裡沒有這些，是角色在裡面做的事留下的痕跡。
4. **兩個解析度**：裡面寫實、外面體素。從「沉浸」切到「旁觀」時，畫面也從寫實變成模型感，觀眾立刻感受到尺度變了。
5. **角色有兩份**：微縮版裡還有一個小 Clawd，同時大 Clawd 從鍵帽裡彈出來。它「既在裡面，也在外面」。

**對照入場轉場（27–28.4s）**，兩者是鏡像：

| | 入場（鑽進去） | 出場（拉出來） |
|---|---|---|
| 方向 | 從上往下，鏡頭下壓 | 從下往上，鏡頭升起 |
| 介面 | 鍵帽表面起漣漪＋氣泡 | 玻璃球透鏡 |
| 切換後 | 從天空落到寫實草原 | 從俯視寫實切到體素微縮 |
| 音樂 | 收小，進入留白段 | 高頻閃爍上行掃頻 |

## 12. 深挖③：光影設計（逐場景）

全片的光有一個總原則：**每個場景都有一個「有來源的主光」**（螢幕、陽光），再加一個**讓角色跳出來的分離光**，以及**場景自己的發光體**。

### 12.1 終端機內部（0–11.5s）

- **主光**：正上方偏前的大面積柔光，角色頂面亮、底下有一團柔和的接觸陰影。
- **成形時的輻射光**：2D 像素拼合時，角色底部往地面打出一圈**橘色的光暈**（像 LED 顯示的溢光），光在暗藍地面上散開。
- **環境**：近黑的藍色虛空，「程式碼」是灰白色發光的膠囊條，有深度、有景深虛化。
- **反光地面**：桌面或螢幕底部是光滑的深色材質，看得到角色腿的倒影和一道冷白色的地面高光（11–12s）。
- **光掃**：9.5–10s 一道光帶從角色臉上掃過，像螢幕玻璃的反光在移動。這種「移動的高光」讓靜止的畫面也有生命。
- **穿屏光膜**：10.5–12s，螢幕玻璃被表現成一道**半球形、白色、邊緣最亮**的光膜（菲涅爾效果），角色穿過時被光膜切開、邊緣溢光。

### 12.2 房間全景（8–9s）

- 夜晚。**唯一的主光源是螢幕**：滿屏程式碼的冷光照亮鍵盤頂部和桌面。
- 窗外是深藍色夜空和松樹剪影，提供冷色的背景層次。
- 低照度、高對比，這個鏡頭的作用是讓觀眾記住「這是一個深夜還在寫程式的房間」。

### 12.3 鍵盤（11.5–28.4s、52–59s）

- **主光**：來自後上方的螢幕，冷白偏藍。在每顆鍵帽**頂面形成一條柔和的白色反光**，側壁有亮邊。
- **鍵帽自發光**：每顆鍵帽裡的地景自己會發光（像燈箱），光透過樹脂往外溢，把相鄰鍵帽的側壁染上對應顏色（水鍵染青、草鍵染綠）。
- **紅光鍵**：持續發出紅色光暈（bloom），染紅周圍一圈。
- **角色受光**：頂面冷白（螢幕），底面暖粉（腳下鍵帽的透射光），兩側較暗。**冷頂暖底**讓角色立體又像站在光源上。
- **景深**：極淺。前景鍵帽大幅虛化成光斑，強化微距感。
- **亮度弧線**：見 10.3，第一次經過時大部分鍵是暗的，回來時全亮。

### 12.4 鍵帽裡的草原（28.4–51.9s）

- **主光**：左上方的暖陽（偏午後），角色左上方受光，右下方有柔和陰影。
- **逆光草葉**：鏡頭常對著光源方向拍，草葉邊緣透光發亮（半透明綠），形成整片「發光的草」。
- **露珠**：草葉上的小水珠是一顆顆小高光點，增加精緻度。
- **葉影**：30.5s 角色臉上有一片清楚的葉子陰影，證明光源有實際方向且前景有遮擋。
- **大氣透視**：遠處樹林被藍白色薄霧罩住，低對比、偏藍（`#9CB8E2`）。
- **光暈與光束**：雛菊和草尖有輕微的 bloom；38.5s 有一道綠色的光束斜穿樹冠（鏡頭光暈或丁達爾效果），標記「魔法發生了」。
- **地面發光點**：33–36s 游標被種下後，地面留下一個暖橘色的小光點，是唯一的暖色光源，引導視線。
- **俯視段**：陽光從左上方來，巨人和樹冠在草地上投出柔和的陰影；草地上的白色小花在暗綠色底上像星星。

### 12.5 結尾（54.5–59s）

- 回到暗。主光是螢幕從前上方打下的冷光，照亮角色頂面和鍵帽頂面。
- 螢幕上的 2D 像素 Clawd 是**自發光**的橘色，和下方 3D 角色形成「上：發光的 2D／下：受光的 3D」的對照。
- 畫面上方是大片近黑的負空間，只有一排排灰色的程式碼虛線，讓視線集中在兩個橘色角色之間。

### 12.6 光影設計的通用規則（寫進 skill）

1. **每個光都要有來源**：螢幕、太陽、發光的鍵帽。不要憑空打光。
2. **角色要有分離光**：暗場景靠冷色輪廓光＋暖色底光，亮場景靠逆光邊緣。
3. **讓場景自己發光**：鍵帽、像素 logo、紅光鍵、種下的光點，都是畫面內的光源，同時也是視線的落點。
4. **用亮度講故事**：暗（還沒發生）→ 部分亮（正在發生）→ 全亮（發生了）。
5. **冷暖分工**：環境冷、角色暖；只有「重要事件」才給暖光（成形的橘光、種子的光點）。
6. **景深是光學預設值**：前景虛化幾乎每個鏡頭都有。
