# 審查：看圖、瑕疵清單、評分錨點

> 及格線在 [acceptance.md](acceptance.md)（以基準片為尺的四層驗收）；這份是看圖的方法和品質評分。

Claude 看不到 Blender 視窗。**所有品質判斷只能根據渲染出來的圖**，用 Read 工具逐張看。讀程式碼看不出畫面好不好。

## 1. 看圖流程（每個鏡頭）

1. `blender -b -P build.py -- --shot SXX --stills hero --preset previs` → 讀 `out/stills/SXX_f*.png`。
2. `python3 edit.py compare SXX` 產生「基準幀 | 你的幀」並排圖，對照 acceptance.md 該鏡頭的驗收卡。
3. 逐條過第 2 節的瑕疵清單。有問題 → 改腳本 → 重建 → 再看。
4. 構圖和動作都過了，再用 `--preset look` 渲染 1–2 張全解析度，看材質和光（第 2 節的「質感」部分）。
5. 鍵帽特寫鏡頭加渲染一張 `cycles_draft`，比對透明是否正確。
6. 整段低解析度渲染後，用 `edit.py sheet` 看節奏，用 `edit.py strip` 看每個接縫。

**修改後一定重新看圖**，不能憑「應該好了」交付。

## 2. 瑕疵清單

**構圖與可讀性**
- [ ] 這張圖一眼看得出主體和正在發生的事
- [ ] 主體不在正中央（除非刻意對稱）；有前景、中景、背景三層
- [ ] 前景有虛化；焦點落在角色眼睛
- [ ] 沒有東西被畫面邊緣切得很尷尬（腳、眼睛）

**角色**
- [ ] 比例正確（身體 9:6:6、手臂在中段、四隻腳）、橘色正確
- [ ] 腳踩在表面上（沒有陷入、沒有懸空），每個接觸點有陰影
- [ ] 動作有預備、壓扁拉伸、落地緩衝；跳躍走弧線
- [ ] 靜止超過一秒的角色有 idle 呼吸

**世界**
- [ ] 地標位置和 `layout` 一致；同一世界的鏡頭之間對得上
- [ ] 鍵帽的點亮狀態符合 `lit_trail`（該亮的亮、不該亮的暗）
- [ ] 沒有穿模（分身穿過地面、角色穿過鍵帽、樹冠穿過巨人）
- [ ] 橘色只出現在角色系統

**質感**（`look`／`cycles` 圖）
- [ ] 黏土啞光、有暖邊、特寫看得到顆粒
- [ ] 鍵帽有折射和亮邊、頂面霧、裡面比外面亮
- [ ] 草有透光和露珠高光；遠景有空氣感
- [ ] 發光物照亮了周圍；沒有死黑或過曝的大面積

**光**
- [ ] 主光來源明確；角色和背景分得開
- [ ] 段落亮度符合能量曲線

**運動與轉場**（strip／sheet）
- [ ] 沒有線性移動、瞬停、抖動
- [ ] 接縫兩側運動方向延續；換世界時穿過介面
- [ ] 切點和動作高點在拍點上

## 3. 八項評分錨點

| 分數 | 意思 |
|---|---|
| 5 | 和基準片同級或更好，挑不出問題；有自己的巧思 |
| 4 | 和基準片同級，有 1–2 個只有放大才看得到的小瑕疵 |
| 3 | 看得出想做什麼，但有明顯瑕疵（穿模、平光、等速、版圖對不上） |
| 2 | 結構在，但畫面粗糙或敘事不通 |
| 1 | 佔位品 |

各項 4 分的具體門檻：

| 項目 | 4 分要做到 |
|---|---|
| 概念與母題 | 九步配方全部到位；母題 ≥ 4 次且結尾回收 |
| 世界連續性 | 所有地標對位；點亮狀態和改變跨鏡頭保留，結尾看得見 |
| 角色一致與表演 | 每個鏡頭有表演動作；所有跳躍落地有壓扁回彈 |
| 材質 | 第 2 節「質感」全部通過 |
| 光影 | lighting.md 第 7 節全部通過 |
| 鏡頭語言 | camera.md 第 6 節全部通過；景別有變化 |
| 轉場 | transitions.md 第 5 節全部通過 |
| 節奏 | `edit.py check` 通過；奇觀在重拍上；能量曲線先收後放 |

自評時每一項寫：分數、證據圖檔名、為什麼不是更高一分。
